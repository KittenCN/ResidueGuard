# 05｜阶段开发计划与任务拆解

## 5.1 实施方式
按风险门槛推进，不以“把所有页面画完”当完成。每个阶段产出源码、测试、实际验证证据和明确限制。没有真实 Mac 环境时可做纯逻辑/夹具工作，但不得通过写一个 pass 断言假装完成系统能力测试。

估算不采用固定天数承诺。最大不确定性在系统版本适配、身份误判和特权执行安全，不在 GUI 控件数量。P0 先消除这些不确定性，再安排迭代与人员。

## 5.2 P0｜环境与能力验证（正式开发前置门槛）

### P0-01 环境基线
执行随附只读 preflight，记录实际 macOS 版本/build、架构、Xcode、Swift、SDK 和签名方式。检查已有 git，不覆盖已有工作。未安装完整 Xcode时报告，不自动下载安装。输出 `docs/validation/environment.md`，明确没有执行任何系统清理。

### P0-02 来源清单与只读样本
验证本机启动配置范围、可用诊断工具、输出大小、权限要求、各用户域边界。读取本机 `man launchctl`、`man launchd.plist`、`man tccutil`；记录工具版本/OS build。BTM 原始输出可能包含个人软件数据，采样需用户知情且脱敏。

输出 `docs/validation/provider-dossier.md` 与脱敏 fixture，说明每个字段来源、未知字段、解析损失和覆盖限制。

### P0-03 隔离测试应用
在可回滚 macOS VM/独立测试账号中建立本项目自有签名测试 app 和 helper。分别创建普通登录项、用户 LaunchAgent、共享配置、SMAppService 自身服务以及测试用隐私请求。测试软件使用专有名称与目录，不复用用户实际应用。

验证移动 app、移到废纸篓、真正删除、重装相同标识、不同路径副本、外部卷离线等场景。系统操作必须有快照和可追踪清单。

### P0-04 权限能力试验
分开验证枚举、按 app 重置、按权限类别重置、结果验证、UI 历史记录变化。覆盖已安装和真正已卸载的 bundle ID、路径型 client、自动化调用者/被控者、不同用户/系统 scope。

macOS 27 不做 TCC 绕过实验；直接读取能力记录为不支持，并寻找公开替代能力，但不预设一定存在。发生 bundle ID 不可解析时记录失败，严禁全量重置兜底。没有 VM 则此任务标未验证，绝不在日常系统替代测试。

### P0-05 helper 可行性和分发
证明所用 SDK 下公开 XPC peer 校验方案、ServiceManagement helper 生命周期、开发签名和用户批准流程。记录 App Store 非目标的理由、最小权限和必要签名配置。不安装真实清理 helper 于日常系统。

### P0 通过条件
生成基于模板的 `docs/validation/capability-matrix.json`：每项有 OS build、证据文件、枚举能力、修改能力、后置验证和限制。没有证据的 mutation capability 一律 false/unverified。

如发现某类无法完整枚举或逐项清理，落实为产品 guidedOnly，而不是留一个会自动调用危险兜底的 TODO。P0 可以按未验证项关闭写能力进入 P1，不允许拿“待验证”充当支持。

## 5.3 P1｜原生工程、核心策略与只读 GUI
P1-01：创建 Xcode App 与 Swift Package，固定 build scheme、bundle ID，建立多文件结构和依赖注入。

P1-02：实现基础模型、来源覆盖、存在状态、能力描述、计划模型和确认策略纯函数。先用合成 fixture 覆盖边界。

P1-03：实现侧栏、表格、检查器、搜索、筛选、空状态、无权限状态和未知状态；清理勾选与表格选中独立。

P1-04：实现所有指定权限分类的正确入口，unsupported 页面不是 TODO 空白页。Mock 模式窗口带明显“演示数据”，默认构建不能把 mock 静默当真实数据。

P1-05：建立项目专用 build_and_run、test 脚本；依官方 skill 的当前 bootstrap 配置 Codex Run。GUI 以 .app 启动。

完成门槛：干净构建；核心策略和 UI 测试通过；fixture 下全红一次、正常两次、混合两次、未知阻断；UI 不执行系统写操作。

## 5.4 P2｜真实只读扫描与保守识别
P2-01：实现安全文件/ProcessRunner，具备取消、超时、输出上限和错误分类。

P2-02：接入应用索引与目标路径检查；多副本、外置盘、Trash、独立 CLI、符号链接和共享组件。

P2-03：接入 launchd 配置、已验证运行信息、BTM 和可用登录项 provider；保留 raw provenance 和覆盖指标。

P2-04：实现 OwnershipGraph 和 OrphanClassifier，证据面板、保护/忽略规则、只读应用关联页。

P2-05：快照比较、局部复扫、扫描代次与可见更新；无需安装 helper 获得有用结果。

完成门槛：真实样本逐行核对，无法解析或访问的数据明确显示；测试范围内不出现“外置盘离线/应用搬家/共享活跃组件被标红”的误判；新增来源无静默丢行。

## 5.5 P3｜用户级精确清理、日志与恢复
P3-01：实现不可变计划器、影响集合展开、去重、过期和 fingerprint。

P3-02：实现真实两级确认状态机、取消和重复提交保护。

P3-03：实现本用户备份/隔离与 manifest 校验、逐步 journal。

P3-04：仅开放经验证的当前用户启动配置操作。先在 VM 清理自有测试记录，再验证后台历史延迟报告。

P3-05：实现配置恢复、恢复冲突和崩溃后只读恢复向导；不自动启动服务。

完成门槛：任何修改之前有完整备份和所需确认；失败、竞争、磁盘满、恢复冲突测试通过；不涉及 root 或全局重置。这个阶段即构成首个有实际价值的清理版本。

## 5.6 P4｜受控特权组件与共享/系统配置
P4-01：自身 helper 签名、批准、按需唤起、升级和移除。

P4-02：实现版本化 XPC DTO、连接身份认证、授权校验和一次性计划 token。

P4-03：helper 自行核验白名单、目录 owner/权限、源指纹、运行身份和 root-owned 备份。

P4-04：在 VM 验证共享 LaunchAgent 多会话影响、系统 daemon、认证拒绝和 helper 被终止场景。

P4-05：安全回归：伪客户端、不同用户、同 Team 非授权程序、篡改 token、路径穿越、symlink/hardlink、重放、过期。

完成门槛：所有特权安全用例通过并保留证据；公开 API 使用得到实际 SDK 验证；未知共享影响不执行。不能为了交付日期降级为任意 sudo shell。

## 5.7 P5｜权限适配、限制与手动工作流
P5-01：分类注册表、每个类别的能力和本地化系统设置路线。

P5-02：在合格旧版 profile 上实现可选只读 TCC adapter；新版明确拒绝直读。schema/权限失败仍有可用 UI。

P5-03：接入经过 P0/新测试验证的精确 reset adapter。缺失 bundle、不支持 client、关系范围扩大等错误无危险兜底。

P5-04：权限记录与应用关联、历史快照对照、引导用户手动处理；“不可读取”与“没有记录”区分。

P5-05：各种显示延迟和无法验证情况报告为 pending/unverified，不写假的成功提示。

完成门槛：用户不会误认为现代系统可以枚举全部权限；已验证的能力逐项附证据；未支持项都有合理引导；不修改私有数据库。

## 5.8 P6｜产品稳定、发布与自清理
P6-01：性能、取消、10,000 条合成数据、UI 可访问性/键盘/高对比度测试。

P6-02：扫描数据脱敏、日志保留、CSV/JSON 安全导出、忽略规则过期行为。

P6-03：多 OS 能力回归、未识别 build 的只读降级、签名身份变更和版本升级。

P6-04：Developer ID、公证、安装包、首次运行、用户拒绝授权、卸载本工具和 helper 的完整路径。

P6-05：编写用户手册与“哪些项目无法清理”的公开说明。

发布门槛：没有会导致错误/越权删除的未解决问题；每个开放 mutation 都有真实集成证据；不能通过“只在我电脑上看起来能用”验收。

## 5.9 后续版本
优先次序：只读应用变化监听 → 更丰富的官方/厂商卸载引导 → 系统扩展和额外启动来源只读检查 → 用户主动打开的设置辅助观察。每一个新来源都复用完整能力、证据、影响、确认和日志机制。

## 5.10 每个任务的 Definition of Done
必须提交：实现范围、变更文件、模型和接口变化、单元/集成/UI 测试的真实命令与结果、使用的 OS/SDK、未解决限制、权限/副作用清单、对应文档更新。不能只提交“已实现功能”的自然语言总结。

测试标记只能为 passed / failed / skipped / notRun，并注明原因。`notRun` 不可并入通过数量。提交前检查不存在私钥、证书、真实权限数据库、用户软件完整名单或未脱敏路径。
