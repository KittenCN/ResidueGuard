# 01｜产品、页面与交互规格

## 1.1 主窗口结构
默认窗口建议 1220×780，最小 980×640，允许缩放。采用侧栏、主表格、可折叠详情检查器。原生浅色/深色和高对比度适配；不以自制透明背景覆盖系统侧栏。

侧栏分组：
- 工作台：总览、应用关联。
- 启动与后台：登录项、后台登记、启动服务（用户代理/共享代理/系统守护进程）。
- 权限：各权限子页、其他/未知类别。
- 管理：操作历史与恢复、忽略规则。
应用偏好使用独立 Settings 场景，不挤进工具内容页。

## 1.2 公共表格
表头：清理复选框｜图标与软件名称｜存在状态｜登记/运行状态｜来源/用户范围｜可用操作。

详情中显示完整 bundle ID、Team ID、签名状态、真实路径、服务 Label、来源文件、来源记录标识、归属证据、判定理由、依赖关系、覆盖缺口和扫描时间。显示名称可友好化，但复制和审计使用完整标识。

默认显示所有已枚举记录，不默认只看红色。提供名称、bundle ID、路径搜索；状态、来源、范围过滤；稳定排序；“仅残留”是用户选择的过滤条件。首次进入没有任何勾选项。

多条底层记录可按软件分组，但所有子项都可展开；组复选框为三态，只勾选可操作子项，旁边明确显示“另有 N 项不可操作”。同软件不同安装路径/用户/签名身份不得被压成一个不可追溯的操作目标。

## 1.3 状态呈现
| 状态 | 展示 | 可勾选清理 |
|---|---|---|
| 已安装/有效独立程序 | 正常文字，显示应用或二进制路径 | 有精确操作能力时可选，双确认 |
| 高可信残留 | 红色名称 + 残留图标 + “高可信残留” | 可执行时可选；全部该类可一次确认 |
| 疑似残留/归属未知 | 黄色提示 + 具体缺失证据 | v1 禁止清理；可复扫/补充扫描目录 |
| 外置盘离线 | 黄色磁盘图标 + “原卷未连接” | 禁止 |
| 路径无访问权限 | 黄色锁 + “未能核实” | 禁止；解释授权范围 |
| 应用在废纸篓 | 黄色 + “尚在废纸篓” | v1 禁止按已删除处理 |
| 共享组件仍有有效归属 | 正常/黄色 + “其他应用仍在使用” | v1 保护，不混入残留清理 |
| 系统/受管理/受保护 | 灰色锁和保护原因 | 禁用 |
| 记录存在但不支持逐项操作 | 保留存在状态颜色，另显示“需系统设置处理” | 禁用，提供引导 |

颜色必须同时搭配文字/图标，不能让色觉差异用户无法理解。红色仅表达存在性判断，不表达恶意或安全漏洞。

## 1.4 总览页
显示本次扫描时间、扫描范围、已读取记录数、高可信残留数、可直接清理数、需手动处理数、未覆盖来源数。不要显示“安全评分 99 分”或把条目数量换算成虚假的提速承诺。

每个来源有覆盖卡片：成功（在声明范围内）、部分、权限不足、不支持、失败、取消。非完整状态附带原因与可行下一步。“权限总表不可读取”应明确而醒目，不能在页脚藏一行小字。

## 1.5 登录项页
表达的是登录后启动行为，不混称“正在运行”。展示可识别项目及来源。对于旧式登录项、应用自行注册的登录项、BTM 派生项，必须显示类型；无法直接操作的类型不伪装为可关闭开关。

受支持的“去系统设置”优先使用公开接口；深层权限链接只是可失败的便利入口，必须有“系统设置 → 相应页面”的文字路径兜底 [S02]。

## 1.6 后台登记页
同时展示系统报告的登记状态、当前可获得的服务运行信息和对应软件存在状态；无法观测运行状态显示“未知”，不是“未运行”。保留来源记录；同一个后台组件出现在启动服务页时通过关联跳转避免用户误认为是两个不同文件。

后台登记清理结果单独汇报：例如“来源配置已隔离；服务已停止；后台历史显示尚未更新”。不得把“配置文件已删除”写成“后台列表已彻底清空”。

## 1.7 启动服务页
子页分别对应当前用户代理、共享代理、系统守护进程；系统自带项以只读方式显示。字段包括 Label、Program/ProgramArguments 的安全摘要、加载域、是否已注册/运行、来源 plist、归属软件。

“停用”和“清理”是不同动作。首期只对验证过的机制开放精确操作；不能为了实现按钮而修改不明字段。清理是备份后卸载并隔离配置，不是卸载整套应用。

## 1.8 权限页面
提供辅助功能、完全磁盘访问、屏幕/系统音频录制、输入监控、摄像头、麦克风、自动化、文件与文件夹、通讯录/日历/提醒事项、照片、蓝牙、语音识别、开发者工具等分类入口。名称按实际系统和本地化核验；不假定一个可见 UI 项只对应一个后台权限键。

本地网络、定位、通知等显示为独立能力，不强行套进 TCC。某类没有可用提供器时，页面显示“当前系统未提供可用的完整列表读取方式”，附手动入口，不显示 0 个应用。

自动化权限需要调用者 → 被控制者关系。用户选择某个关系行时，后端若只能重置调用者的全部自动化授权，必须重建更大范围的操作预览并要求重新选择/确认；不能删除一个关系却实际影响所有关系。

授权值保留原始语义：允许、拒绝、受限、未知、受管理；不能把所有非零值都当允许。历史或导入记录明确标“历史快照，不代表当前状态”，并且不能直接作为写操作依据。

## 1.9 应用关联页
按稳定身份展示一个软件关联的所有登录、后台、服务与已知权限记录。对多个安装副本显示路径和签名身份。点击“查看关联记录”不会自动勾选；跨来源操作必须经过统一计划器合并与去重。

首期可先做只读关联，不做跨页面勾选购物车。v1 选择状态限当前页面，切换页面清除勾选并提示；同页改变过滤时保留勾选，但明确显示“已选 N 项，其中 M 项当前隐藏”，提供“查看全部已选”。

## 1.10 扫描与授权
首次启动只解释功能，不同时弹出全部权限申请。普通扫描先完成可读取范围；用户主动点“补充授权”后说明某权限能改善什么、仍不能做到什么，再打开相应系统界面。不要求摄像头/麦克风实际使用权限来读取别人的授权记录。

扫描支持取消、部分结果和增量更新。刷新不能把旧行误当新结果；UI 带 generation/time，清理计划使用最新确认过的代次。连续点击扫描合并任务，不并行启动无限次遍历。

## 1.11 清理确认界面
按钮“检查所选操作”只生成计划，不计为确认。第一次确认页展示实际项目数、应用数、操作类别、路径、影响范围、可恢复性、需管理员认证事项。

全部影响目标是红色残留：按钮“确认清理这 N 项”。
包含已安装软件：第一次按钮“继续检查风险”；第二次独立页面醒目标出仍安装的软件与后果，要求输入“清理仍安装软件的设置”，再点“再次确认清理”。不得让一个 Enter 或双击连续跳过两个页面。取消随时有效直到当前操作开始修改。

未知、受保护、无操作能力项不是“增加一次确认就能清理”，而是计划阻断。系统认证弹窗在产品确认之后发生；拒绝认证不会触发部分偷偷清理。

## 1.12 历史、恢复和设置
历史展示计划摘要、每个动作状态、备份位置/校验值、是否涉及运行状态、实际结果、剩余手动操作。恢复启动配置和重新运行服务分别授权；恢复权限授权不提供一键按钮。

设置包括扫描根目录、忽略/保留规则、诊断日志保留期限、备份保留策略、帮助和自身辅助程序状态。默认不启动后台监控、不随登录启动、不发送网络遥测。辅助程序安装/升级/移除都在可见界面管理。

## 1.13 关键中文文案
- “此列表包含本次成功读取的记录；另有 2 个来源未读取。”
- “未找到程序，但原安装卷尚未连接，不能确定已经卸载。”
- “这是系统保护项目，当前工具不提供清理。”
- “当前系统无法完整读取此类权限，请在系统设置中核对。”
- “操作会重置该应用对此类别的授权，下次访问可能重新询问；这不等于恢复出厂设置。”
- “命令已执行，但暂时无法验证系统界面中的历史条目是否移除。”
