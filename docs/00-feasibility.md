# 00｜可行性、能力边界与产品范围

## 0.1 结论
可以开发，而且启动/后台残留治理具备实用价值；但不能把“各类权限的全部应用均能完整列出并任意逐项清理”作为所有 macOS 版本上的无条件承诺。项目必须按数据来源分别声明可枚举、可判断、可修改、可验证和可恢复的程度，而不是只有一个 `canClean` 开关。

本项目不要求关闭系统保护，不修改私有数据库，不替用户批准隐私权限。能力不足时提供明确的系统设置引导。这样的限制是正式产品行为，不是隐藏的 TODO。

## 0.2 原始需求到可验收需求
| 原始目标 | 正式规格 |
|---|---|
| GUI 多页面 | 原生侧栏 + 分类表格 + 详情检查器，每类独立入口和覆盖状态 |
| 展示所有软件 | 展示已声明来源、已授权范围中成功枚举的全部记录，包括正常、残留、未知、被保护记录；未知/失败单列，不悄悄丢行 |
| 删除的软件标红 | 只有证据达到高可信门槛才标红；无法访问、外置盘离线等不当作删除 |
| 提示可清理 | 同时满足高可信残留和精确操作能力才显示“可清理”；否则“残留，需系统设置处理” |
| 名称前多选框 | 可操作记录有复选框；不可操作记录保留禁用复选框和原因；详情选中不等于清理勾选 |
| 正常软件至少两次确认 | 按实际影响集合计算，只要有已安装软件，必须完成两次独立应用内确认 |
| 全红一次确认 | 仅限实际影响全部为高可信残留且无范围外影响的可执行计划；系统认证额外发生 |

“完整”的约束对象是来源和扫描范围，不是整个系统隐私设置的绝对镜像。每页必须显示来源、范围、时间、失败项与未覆盖项。

## 0.3 能力分层矩阵
下面是设计基线，不是已经实测的兼容承诺。P0 必须按实际 OS build 验证。

| 类别 | 可见性方案 | 清理方案 | 首期边界 |
|---|---|---|---|
| 用户 LaunchAgents | 读取本用户配置，关联运行时信息 | 备份、卸载精确服务、隔离配置 | 优先完成；已安装关联也允许双确认后处理 |
| 共享 LaunchAgents / LaunchDaemons | 读取系统共享配置；权限不足明确报告 | 狭窄提权辅助程序执行已验证计划 | 需管理员认证和影响范围核验；不读别的用户私密目录 |
| 系统自带启动服务 | 可访问时只读展示 | 不提供清理 | 禁用复选框，说明系统保护 |
| 登录时打开项目 | BTM/其他经验证来源，必要时独立旧式适配器 | 仅对有稳定、可验证逐项机制的记录执行；其余引导设置 | 不承诺所有类型可写 |
| BTM 后台登记 | 解析诊断输出，保留无法识别记录 | 清理可证实的来源配置；登记历史无可靠逐项操作则引导 | 来源文件消失不代表登记历史已经消失 |
| TCC 类权限 | 旧系统可选只读适配器；当前系统按能力降级 | 经验证的精确 `tccutil` 重置，或手动引导 | 不保证已卸载 bundle 可重置，不保证 UI 历史行消失 |
| macOS 27+ 权限总表 | 不使用 TCC 直读；显示可合法获知的信息和不可读状态 | 能力验证后限定重置；否则设置引导 | 不承诺系统设置全部应用列表 |
| 本地网络、定位等 | 按独立机制处理，默认引导 | 不套用猜测出来的 TCC service 名称 | 不把所有权限视为同一种数据 |
| MDM 管理项 | 能识别则标记；策略可见性不足也记录 | 不擅自改企业配置 | 禁用清理；提示联系管理员 |
| 第三方特权组件、系统扩展 | 后续只读关联展示 | 厂商卸载器或系统官方流程 | 不通过删除二进制“强制卸载” |

## 0.4 不能绕开的平台事实
后台登记诊断工具不是稳定的通用管理数据库接口 [S01]。官方服务管理对象针对应用自身包含的服务 [S02]。macOS 27 变更直接影响旧式权限数据库读取方案 [S03]。Apple 工程师建议使用各功能所属框架提供的权限 API，但这不代表获得读取所有第三方应用权限的接口 [S04]。

一些开发者报告，应用卸载后按 bundle ID 重置权限会出现找不到标识的错误；这属于必须在目标系统复现的风险，而非所有版本一定如此 [S06]。本地网络权限的重置能力另有官方限制 [S08]。

## 0.5 首期明确不做
不做缓存、照片、聊天记录或浏览器数据清理；不做“内存加速”；不强制卸载应用；不把未签名等同恶意；不通过网络查询/上传全部软件清单；不做全局后台数据库重建；不恢复、伪造或自动批准隐私授权；不按软件名称模糊匹配后批量删除目录。

关闭系统保护、篡改私有数据、用重建假应用骗过标识校验、以 root 运行整个 GUI，都不属于“高级模式”。本项目不提供这些模式。

## 0.6 目标系统与降级
建议部署目标 macOS 14+，优先 Apple Silicon。14、15、26、27 分别设置能力配置；不假定版本号连续。Intel 支持由实际测试和构建资源决定，不在未验证时宣称已支持。系统版本仅用于选择候选适配器，实际构建号和运行时能力探测共同决定功能开放。

新主版本未验证：继续显示已支持的只读信息；禁用未经验证的修改路径。解析器遇到新输出：保留原始文本和错误，不返回“扫描成功、0 项”。即使旧版本具备更多读取能力，也不要求用户降级系统。

## 0.7 推荐的额外功能
高优先级：解释判定证据；运行状态和登记状态分离；软件跨页面关联；操作预览；备份和恢复；未知原因可追溯；扫描覆盖率；变更历史；导出脱敏报告；忽略/保留规则；自身辅助程序的透明卸载。

次优先级：应用移动/卸载后的增量复扫；用户开启时才启用的变化监测；第三方卸载器提示；系统扩展只读页；只显示实际已观测行的系统设置辅助读取实验。

不建议首期投入：自动后台清理、全盘无限递归扫描、持续进程监控、云端信誉评分、全量权限修复。它们会扩大隐私、安全与维护成本，却不解决首期最关键的误判问题。
